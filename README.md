## Принятые решения
- для вводимых переменных используем тип int, 
- для суммарного времени будем использовать тип long
- для ввода используем BufferedReader (быстрее scanner)
- ресурсы закрываем через try-with-resources
- предполагаем, что ось X направлена вправо, ось Y вниз, тогда повороты:  
  - right: (dx, dy) -> (dy, -dx)  
  - left:  (dx, dy) -> (-dy, dx)
- чтобы объединить все состояние минотавра написан класс Minotaur, вся логика обновления состояния в методах класса
- для удобной работы с координатами добавлен иммутабельный класс Coordinates, после раздумий был заменен на record, так как большинство необходимых методов доступны автоматически
- методы rotate и add возвращают новый объект, так как мы используем coordinates как ключик в map и set
- поскольку форма и размер массива неизвестны, информацию об известных клетках принято хранить в сете visited и мапе info
- при этом не забываем добавить в них стартовую клетку


## Размышления по задаче
Пишем алгоритм для минотавра, выводим совершаемое действие в stdout, 
получаем ответ снаружи в stdin, читаем его и работаем дальше

Идейно решение такое
1. читаем 8 чисел 
2. цикл:
   - решаем какое действие сделать
   - отправляем команду
   - читаем ответ от системы
   - обновляем состояние или стратегию
3. когда уверены, что обошли все, то оправляем 4 и время

### про лабиринт
 - Лабиринт произвольной формы
 - Минотавр смотрит в определенную клетку, шагает только вперед
  Направление можно задать вектором ((x_1 - x), (y_1 - y)) = (dx, dy)
- Доступен поворот на 90 градусов в любую из сторон
- Можно развести костер, позволяет посмотреть на K клеток вокруг
(считаем K радиусом видимой области, квадрат стороной 2 * K + 1)
- У каждого действия есть своя цена (временная)
- Нужно обойти клетки за мин время
- '#' - стена, '_' - пустота
